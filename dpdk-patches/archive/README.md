# 历史补丁与脚本 —— 不要用于当前安装

当前入口是 [规范补丁序列](../../patches/README.md)。这里保留早期 `step*.py`、
`fix_vec.py`、辅助源码快照和旧 diff，仅供追溯。它们不是当前实现，运行可能
覆盖已验证的代码。下面记录的是其中两个明确被否决的脚本。

这些脚本会生成**已被审查否决**的实现。保留仅供追溯，执行会覆盖
正确版本。

| 脚本 | 其中被否决的部分 |
|---|---|
| `fix1.py` | TX 距离校验缺少单调性（只比 `wqe_ci - new_pi`，未保证 `new_pi` 相对旧值前进）；`open()` 任何失败都判为非 CVM |
| `fix6.py` | 向量路径"钳制到 1"——按整个 CQ 容量比较而非剩余连续容量；32 位 `byte_cnt` 截断后才校验；链式累计未检查；标量坏 CQE 可能重复 reset；包长只查 `UINT16_MAX`，且放在 `mlx5_rx_poll_len` 内会破坏 MPRQ 的打包字段 |

正确的边界逻辑见仓库根目录 `bounds-test.c`，19 个用例覆盖环尾、
32 位截断、链式累计、按 mbuf 实际可写空间的包长校验。

**接入时注意**（审查第 3 条）：`cap` 的语义必须二选一，不能混用 ——
要么固定为入口总预算并用 `acc + raw <= cap`，要么每段传递递减后的
`remaining` 只查 `raw <= remaining`。两者同时做会重复扣减。

预算至少应取三者最小值：CQ 连续剩余项、elts 连续剩余项、
当前已投递且可消费的 mbuf 数。
